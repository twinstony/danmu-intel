# ADR-0004 收款地址生成

## 状态：已接受

## 上下文

需求 FR-C6-2：每位用户专属收款地址。需求 NFR-S-1：永不持有可动用资产凭据。Polygon 支持 BIP44 派生（`m/44'/60'/0'/0/i`），Solana 技术上可派生但流程重。

## 决策

- **Polygon**：用户提供 **xpub**（watch-only 公开信息，非私钥）→ 系统按 BIP44 规范派生 `m/44'/60'/0'/0/i` 地址，索引只前进不回退（防串单）。私钥永不出硬件钱包。
- **Solana**：使用**单一收款地址 + 每单唯一 memo**（需求允许"唯一标识"替代唯一地址）。
- **系统绝不持有**：私钥、助记词、加密 keystore、助记文件。只持有 xpub + 派生索引 + 收款地址 + memo。
- **钱包品牌**：代码/设计/文档中不出现任何钱包品牌名（历史教训：Rabbit Wallet 被误写为 MetaMask）。

## 后果

- ✅ Polygon 可派生 2³¹ 个地址（每个用户一个绰绰有余）。
- ✅ Solana memo 方案已在 Solana 支付标准中广泛采用（如 Helius DAS API 支持按 memo 查询）。
- ⚠ Solana 单地址方案：同一时刻多笔同额订单需依赖 memo 区分，**金额尾数策略**（每单带唯一小额尾数）降低同额冲突概率。
- ⚠ xpub 一旦泄露，所有派生地址暴露（但资金仍然安全——派生地址私钥由运营者硬件钱包控制）。
