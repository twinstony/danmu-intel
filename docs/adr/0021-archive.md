# ADR-0021 归档：6 个月压缩迁 NAS 挂载点、索引行改指向归档件、内容摘要不动

## 状态：已接受

## 上下文

需求 §7.10 / NFR-D-1..4、AC-17；设计 §5.3；ADR-0002（`6 个月后归档：压缩为 .jsonl.zst 迁至
NAS，DB 索引行保留 rel_path 改指向归档挂载点`）、ADR-0013（统计可重建）、ADR-0018（统计明细
90 天 → 汇总后删）。

设计与需求把「要什么」写清楚了，**没写到实现级**的有几件事：

- 「迁 NAS」在单机上具体是什么？`smb://ocean.local/…` 谁挂、挂在哪、`rel_path` 怎么还能
  「相对数据根」？
- **报告里冻结的溯源引用**怎么办？报告存的是 `raw/…jsonl` + 行范围 + SHA256（T5），而
  ADR-0002 要求索引行的 `rel_path` 改指向归档件 —— 两边不再同名。更要命的是 T7 每次发布都会
  把**全部**已发布页面的来源重查一遍（`build_site` 遍历所有 published 版本），所以「归档之日」
  很容易变成「发布闭环坏掉之日」（AC-8 反噬）。
- **哪个校验和算数**？`danmu_segments.sha256` 是压缩前的整文件摘要，归档件是压缩后的字节。
- 压缩用什么？`pyproject.toml` 只有 `aiohttp` 一个依赖，本机没有 pip（装不了 `zstandard`）。
- 归档路上发现「在线件不见了」「在线件与封存值对不上」「`raw/` 里超期却没进索引」怎么办？
- 「不再参与日常统计」（NFR-D-2）是不是意味着顺手把统计也精简掉？

## 决策

1. **归档根 = `<data>/archive`，NAS 由挂载点接入**。不造「远端/本地」两套抽象：把
   `ocean.local` 上的共享挂到 `<data>/archive`，`rel_path` 因此继续是「相对数据根」，
   SourceRef、行范围摘要都不必知道 NAS 存在。归档根**默认必须是独立挂载点**
   （`st_dev` 与数据根不同）：NAS 没挂上时它要么不存在、要么与数据盘同设备，命令**拒绝执行**
   （`--allow-same-disk` 只给本机演练与测试）。否则「迁出在线范围」会静悄悄退化成
   「在同一块盘上换个目录名」。
2. **保留期 = 6 个日历月**，自采集之日算起（日期取自落盘路径 `raw/<platform>/<yyyy-mm-dd>/`）；
   `--months` / `--cutoff` 可覆盖（补跑、演练、测试用）。
3. **压缩用 stdlib `compression.zstd`**（Python 3.14 起自带，`ZSTD_LEVEL = 10`）：为一个批处理
   压缩引第三方包不划算（本机连 pip 都没有），而归档件是普通 zstd 流，NAS 上 `zstd -d`
   直接解得开、不绑定本仓库。`requires-python` 相应提到 `>=3.14`（本机就是 3.14.4）。
4. **索引行 `rel_path` 改指向归档件**（照 ADR-0002 原文）：`archive/<platform>/<yyyy-mm-dd>/
   <room_id>-<hh>.jsonl.zst`；新增 `archived_at`（同一次归档写同一个时刻，按它可查出这次
   归档的完整范围）与 `archive_sha256`（归档件**自身字节**的摘要）。`sha256` **保持压缩前的
   整文件摘要**（封存值）：它才是「内容有没有被改过」的判据，报告的行范围摘要同在这个口径上。
5. **两个地址互为纯函数**（`common/evidence.py`）：`raw/A.jsonl` ↔ `archive/A.jsonl.zst`。
   于是报告里冻结的在线地址照样找得到文件（`locate`：在线件不在就看归档件，`.jsonl.zst`
   透明解压），而发布检查里「整份内容 vs 封存值」的比对按**规范地址**（在线那颗）对齐 ——
   归档既不打断溯源，也不会把这道防线静默变成空转。
6. **归档是「压缩 → 校验 → 才删」**：先比对在线件与封存值（对不上就拒绝归档，不给它背一个假
   封存值）→ 写归档件（同目录 `.part` + `os.replace`）→ 校验解压后内容摘要 == 封存值
   （对不上就丢弃归档件、保留在线件）→ 删在线件 → 更新索引行 + 一条 `archive.run` 审计
   （操作者、截止日、归档几件、字节、**范围两端**、异常清单）。
7. **归档只碰 `danmu_segments` 与 `audit_log`**（源码扫描 + 生命周期测试双重断言）：NFR-D-2 管的
   只是原始弹幕；切片/统计/报告/订单/会员/审计长期不删，报告与订单是账本。统计明细 90 天 →
   `stats_daily` 仍由 T10 的 `site-stats --prune` 负责，本层不重复实现（生命周期 e2e 断言
   它不丢账）。
8. **异常不静默、交人处置**：在线件缺失、摘要对不上、`raw/` 里超期但不在索引里的文件，都进
   `ArchiveRun.anomalies` 并让命令**非零退出**（cron 因此会喊）。不做「顺手删掉」这种不可逆的
   猜测 —— 没进索引的文件不在证据链上，删了就是丢证据。
9. **可调取**：`archive --retrieve <在线地址|归档地址>` 取回**未压缩**内容（取回前先对封存值，
   对不上就拒交），因此归档件能喂给任何读原始记录的路径（`rebuild` 的 AC-13 重算对归档数据
   同样成立）。`archive --verify` 复核全部归档件：文件在 + 归档件自身摘要一致 + 解压后内容
   与封存值一致。取回时**先对归档件自身摘要**（`archive_sha256`）再解压：文件被截断/被改
   就在解压前拒交，用户看到的是一句人话而不是压缩器的 `ZstdError`；
   `common/evidence.py:DamagedArtifact` 是兜底（索引行缺失或没有 `archive_sha256` 时）。
10. **新增列由 `open_db()` 就地补齐**（`common/db.py:ADDED_COLUMNS`）：`CREATE TABLE IF NOT EXISTS`
   对**已存在**的表不补列，而数据目录与库都在仓库外、是活账本 —— 少一列就是「每次归档都在
   `no such column: archived_at` 上裸崩，而且没有过渡路径」（删库重建会丢
   `matches/slices/metrics/…` 与全部索引行，而索引行没有从 `raw/` 重建的命令）。
   因此补列与建表同一个口径：打开时按 `PRAGMA table_info` 幂等 `ALTER TABLE ADD COLUMN`，
   既有行一行不动。这不是兼容层（没有并行新旧路径、没有 fallback），而是把 DDL 对既有表
   真正应用一次。

## 后果

- ✅ AC-17 逐条有落点：到期原始记录被归档（只动保留期外的）、归档件可调取（`--retrieve`）、
  可核验（`--verify` 三查 + 归档件就是原始内容的 zstd 流）、归档动作留痕（`archive.run` +
  索引行的 `archived_at` / `archive_sha256`）。
- ✅ NFR-D-4 有测试：归档后在线保留期内的报告页面仍复核得过（`verify-sources`），整棵站点树
  重建 + 7 项检查照旧通过；往归档件里追加一行仍被「封存摘要」拦下（归档没有把防线变空转）。
- ✅ NFR-D-1/D-2/D-3 都可测：6 个月才动、迁出在线范围（在线件删除 + 索引改指向归档件）、
  审计答得出「何时 + 哪些范围」。
- ✅ 唯一真实实例上可执行：本机数据目录的库是 T1–T12 时代建的（无归档两列），`open_db()`
  就地补齐后 `archive --dry-run` / `archive` 直接能跑，既有账本与四个 raw 件的索引行都在。
- ✅ AC-13 对归档数据也成立：归档件透明解压，`rebuild` 删统计后仅凭归档件重算结果一致。
- ⚠ **NAS 可用性成了归档的唯一外部依赖**：挂载掉了归档就跑不动并报警 —— 这是刻意的取舍
  （宁可喊，也不悄悄把两年弹幕压进同一块盘）。备份/副本策略归 NAS 侧，本仓库不实现备份工具与
  恢复演练（NFR-A-5）。
- ⚠ `archive_sha256` 只防「文件被换/损坏」，防不住整块 NAS 丢数据；抗丢失是 NAS 的
  RAID/快照的事。
- ⚠ 归档把索引行的地址改掉了，`rel_path` 不再是「采集时那个路径」：**任何按 `raw/` 前缀拼
  路径的代码从此都是错的**，读原始记录一律走 `common/evidence.py`（`locate`）。本层已把四个
  入口（统计重算、贡献量、取证引用、发布检查）都收进这个函数。
- ⚠ `raw/` 下的空日期目录不清理（无害）；`raw/` 里超期但未索引的文件会一直让命令非零退出，
  直到人补齐索引或另行处置。
- ⚠ 归档件坏了要人处置（拒交 / 丢弃并重归）：本仓库不做 NAS 侧副本与恢复演练（NFR-A-5）。
- ⚠ 只有一条命令行路径（`danmu-intel archive`），后台不加归档页：T12 的 12 个页面清单是
  写死在测试里的，归档是 cron 批处理（与 `site-stats --prune`、`members --sweep` 同一路子）。
