# ADR-0008 首发采集平台

## 状态：已接受

## 上下文

需求 FR-C1-2：多平台对接，新增平台不得改动已有平台逻辑。架构必须支持四平台（虎牙/SOOP/Twitch/KICK），但"首发真跑哪几个"需拍板。

## 决策

- **架构层**：统一 `Adapter` 协议（`parse_room` / `stream` / `probe`），注册表 `ADAPTERS: dict[str, Adapter]`。**新增平台 = 新增一个模块 + 注册一行，已有代码零改动。**
- **契约测试**（`tests/contract/test_adapter_contract.py`）对每个适配器跑同一套断言：字段齐备、时间单调、非法 payload 不崩、断流触发重连。
- **首发平台**：**只启用虎牙 + SOOP**（蓝图验证过、中文/韩文主源、本地网络可达）。其余留注册表一行。
- **节奏**：符合用户"宁缺毋滥、一点一点上"的原则。

## 后果

- ✅ 架构可扩展到 4+ 平台，但第一版只负担 2 个平台的运维。
- ✅ 契约测试是"新增平台不得改动已有逻辑"的可验证防线。
- ⚠ 首发两个平台的数据采集逻辑差异大（虎牙走内部 SDK、SOOP 走公开 API），开发工作量集中在两个独立适配器上。
