# ADR-0007 后台形态

## 状态：已接受

## 上下文

需求 Q-2：后台可视化配置**第一版必须有**；需求 Q-8：管理员一类角色（不做运营角色）；需求 NFR-S-3：后台与公开面隔离。

## 决策

- **形态**：独立 Python 进程（FastAPI + Jinja2 服务端渲染模板）。
- **访问**：**仅监听 tailnet 接口**（不挂 Funnel），非 tailnet 网络不可达。
- **鉴权**：单管理员口令（哈希存仓库外 `.env`）；登录态为短期签名 cookie（SameSite + HttpOnly）。
- **配置 1 分钟生效**（NFR-T-4）：`config` 读取走进程内 60s TTL 缓存；后台保存后立即失效本进程缓存。采集器子进程通过"配置版本号"感知变更。
- **功能**：概览、比赛管理（状态机操作）、房间与数据源、切片复核、灰信号评审、报告（预览/重生成/发布）、发布与回滚、会员与订单、通知与告警、配置、审计日志、成本与额度。

## 后果

- ✅ 后台不在公网面 → 攻击面极小。
- ✅ Jinja2 服务端渲染 = 零前端构建链（最简实现，符合 AGENTS.md）。
- ⚠ "配置版本号"跨进程传播需要实现（版本号写入 config 表 → 主进程调度循环读取 → 受影响的子进程重启）。
