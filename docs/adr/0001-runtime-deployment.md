# ADR-0001 运行载体与公网入口方案

## 状态：已接受

## 上下文

需求文档要求"单机"（NFR-A-3）、"不做备份恢复演练"（NFR-A-5），同时要公网可访问的站点（NFR-A-1）和 24/7 采集（NFR-T）。用户既选了"在本机 10.0.0.138 开发验证并最终承载"，也选了"页面走蓝图 Vercel 静态部署"。

## 决策

- **运行形态**：本机（10.0.0.138 / tailnet 100.118.248.92）单机承载全部常驻进程；不开额外机器、不引入容器编排。
- **站点形态**：静态骨架 + 免费内容走 Vercel 静态托管（蓝图已验证路线）；**付费段落不进静态产物**，由本机后端 API 凭凭据返回（避免 curl 白嫖）。
- **公网入口**：**Tailscale Funnel（:8443）** 暴露校验 / 统计上报 / 下单三个接口；后台**仅 tailnet 内可达**。
- **限制已确认**：Funnel 只能使用 443/8443/10000 端口、`*.ts.net` 域名、TLS，带宽上限不可配（实测 < 50 Mbps）。因 API 载荷极小（JSON < 2KB/次），带宽瓶颈不构成实际约束。

## 后果

- ✅ 满足"单机" + "公网可访问" + "页面走 Vercel"三个看似矛盾的需求（通过前后端分离化解）。
- ✅ 后端不与 Vercel 直接耦合（蓝本的缺陷是"会员库同步到 Vercel"——我们避免这个耦合）。
- ✅ Funnel 免费、无需域名、无需新装组件（本机已装 Tailscale）。
- ⚠ Funnel 的 ts.net 域名不可换自定义域名；若未来需要自有域名，需加 Cloudflare Tunnel（另起 ADR）。
- ⚠ 本机 IP 变化（如重启 tailscale）自动由 Funnel 跟踪，**不依赖固定 IP**。
