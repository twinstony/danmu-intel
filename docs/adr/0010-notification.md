# ADR-0010 通知通道与时效闸门

## 状态：已接受

## 上下文

需求 FR-C9-2 + NFR-T-5：报警 5 分钟内送达，**超时即丢弃**。用户明示"覆盖所有类型"（健康率/新操作/跨档等）。

## 决策

- **主通道**：QQ Bot API（用户首选通讯渠道）。
- **备通道**：Telegram Bot API。
- **5 分钟时效闸门**：通知入库即 `created_at`；`notifier` 每 30s 扫描；超过 5 分钟未送达 → `state='dropped_expired'`（**销毁，不补发**）；尝试失败重试 2 次（间隔 30s）后同样销毁。
- **抑制与去重**：同 `alert_key` 在冷却期（默认 15 分钟）内只发一次；恢复时发送一次恢复通知。
- **覆盖范围**：所有类型（采集/发布/入账/额度/LLM降级/磁盘/证书）统一走同一个闸门（用户明示，不可有例外）。

## 后果

- ✅ 统一闸门简化实现（一套逻辑覆盖所有事件类型）。
- ✅ 5 分钟丢弃 = 通知"过期即废"，不堆积不骚扰。
- ⚠ "5 分钟"是硬时效，意味着通知投递延迟必须低——需要本机到 QQ Bot / Telegram API 的延迟 < 2s（实测满足）。
- ⚠ 冷却期 15 分钟是默认值，写入 `config` 可调。
